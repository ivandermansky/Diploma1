Набор автоматизированных тестов для проверки функциональности класса Burger в приложении для сборки бургеров. 
Тесты покрывают все основные операции с бургером: добавление/удаление ингредиентов, перемещение, расчёт цены, генерацию чека и установку булочек.

Тесты используют Mockito для создания моков объектов и JUnit Parameterized для параметризованных тестов, что позволяет эффективно проверять множество сценариев.

**Технологии и инструменты**

Java 8+ — язык программирования;

JUnit 4 — фреймворк для тестирования;

Mockito 3+ — создание моков и заглушек;

AssertJ 3+ — расширенные утверждения (assertThat);

Maven — управление зависимостями и сборка.


**Описание тестов**
1. BurgerAddIngredientTest
   Цель: проверить корректность добавления ингредиентов в бургер и обновление цены.

Что тестируется:

- ингредиент добавляется в список ingredients;

- цена бургера увеличивается на стоимость добавленного ингредиента.

**Используемые данные:**

14 различных ингредиентов (булки, соусы, начинки) с разными ценами и типами.

Метод: параметризованный тест JUnit.

2. BurgerEmptyIngredientsTest
   Цель: проверить поведение бургера без ингредиентов.

Что тестируется:

- цена равна удвоенной цене булочки (верхняя + нижняя);

- чек содержит ровно 3 непустые строки: две булочки и строку с ценой.

3. BurgerGetPriceTest
   Цель: проверить правильность расчёта итоговой цены бургера.

Что тестируется:

- итоговая цена = (цена булочки × 2) + сумма цен всех ингредиентов.

Сценарий: сложный состав (булочка + 3 ингредиента).

Метод: параметризованный тест.

4. BurgerGetReceiptTest
   Цель: проверить корректность генерации чека в текстовом формате.

Что тестируется:

- формат чека: верхняя булочка, ингредиенты, нижняя булочка, пустая строка, цена;

- правильное отображение названий и цен;

- нормализация формата (замена запятых на точки, обрезка пробелов).

Сценарии:

- бургер без ингредиентов;

- булка + один соус;

- булка + два ингредиента (соус и начинка);

- булка с несколькими ингредиентами.

Метод: параметризованный тест с нормализацией строк.

5. BurgerMoveIngredientTest
   Цель: проверить корректность перемещения ингредиентов внутри списка.

Что тестируется:

- изменение порядка ингредиентов в списке ingredients после вызова moveIngredient(oldIndex, newIndex).

Сценарии:

- перемещение с конца в начало;

- перемещение с начала в конец;

- перестановка соседних элементов;

- перемещение в середину;

- самоперемещение (индекс не меняется).

Метод: параметризованный тест.

6. BurgerRemoveIngredientTest
   Цель: проверить корректность удаления ингредиентов по индексу.

Что тестируется:

- удаление элемента из списка ingredients по указанному индексу;

- сохранение корректности списка после удаления.

Сценарии:

- удаление первого ингредиента;

- удаление из середины списка;

- удаление единственного ингредиента;

- удаление последнего ингредиента.

Метод: параметризованный тест.

7. BurgerSetBunsTest
   Цель: проверить корректность установки булочек для бургера.

Что тестируется:

- поле bun в объекте Burger ссылается на переданную булочку;

- свойства булочки (имя и цена) сохраняются корректно.

Сценарии:

- установка флюоресцентной булки R2‑D3 (цена 988);

- установка краторной булки N‑200i (цена 1255).

Метод: параметризованный тест.

Принципы тестирования
Изоляция тестов: каждый тест выполняется в своём контексте (@Before / @After).

Использование моков: объекты Bun и Ingredient создаются как моки с помощью Mockito.

Параметризованные тесты: позволяют проверять множество сценариев одним шаблоном.

Валидация результатов: для каждого теста проверяются:

- состояние объекта (Burger);

- возвращаемые значения методов (getPrice, getReceipt);

- структура данных (ingredients).

Нормализация данных: в BurgerGetReceiptTest используется метод normalizeReceipt для сравнения строк чека с учётом возможных различий в форматировании.

**Настройка и запуск**

Предварительные требования:
- Java 8 или выше;

- Maven 3.6+;

- IDE (IntelliJ IDEA, Eclipse) или командная строка.

**Зависимости Maven**

Убедитесь, что в pom.xml присутствуют следующие зависимости:

xml
<dependencies>
<dependency>
<groupId>junit</groupId>
<artifactId>junit</artifactId>
<version>4.13.2</version>
<scope>test</scope>
</dependency>
<dependency>
<groupId>org.mockito</groupId>
<artifactId>mockito-core</artifactId>
<version>5.0.0</version>
<scope>test</scope>
</dependency>
<dependency>
<groupId>org.assertj</groupId>
<artifactId>assertj-core</artifactId>
<version>3.24.2</version>
<scope>test</scope>
</dependency>
</dependencies>


В BurgerGetReceiptTest выводится нормализованный ожидаемый и фактический чек для визуального сравнения.

AssertJ предоставляет подробные сообщения об ошибках при падении тестов.

**Рекомендации по разработке при добавлении новых тестов:**

- Используйте существующие модели данных (Bun, Ingredient, Burger).

- Применяйте параметризованные тесты для схожих сценариев.

- Используйте моки (Mockito) для изоляции тестируемого кода.

- Проверяйте не только возвращаемые значения, но и внутреннее состояние объектов.

- Нормализуйте данные перед сравнением, если формат вывода может варьироваться.

**При отладке:**

- проверяйте логи консоли для сообщений о состоянии объектов;

- убедитесь, что моки настроены корректно (when(...).thenReturn(...));

- при ошибках валидации сверяйте ожидаемые и фактические значения в отчётах AssertJ.
